파셜(include) 사용법

한눈에 보기

같은 마크업을 페이지마다 복사하지 않고 public/html/include/ 파일 하나로 두는 방법. 규칙의 근거는 두 파일이다 — 브라우저 public/js/dynamicImport.js · 산출물 scripts/prerender.js.

이 페이지의 헤더와 왼쪽 메뉴도 파셜이고, 아래 표·예시 카드·데모는 전부 JSON + 템플릿 + 실제 include 로 그린다 — 규약이 깨지면 이 문서가 먼저 무너진다. 문서 판은 docs/PARTIALS.md(같은 JSON 에서 npm run docs 로 찍는다).

1. 기본형

부르는 쪽은 빈 div 하나, 받는 쪽은 조각 마크업

부르는 쪽 — 페이지

<div
	class="dynamic-content"
	data-source="./include/common/_header.html"
	data-page-title="회원 관리"
></div>

받는 쪽 — _header.html

<header class="app-header">
	<h1 class="app-header__title">{{pageTitle|페이지 제목}}</h1>
</header>
파셜 기본 규칙
항목 규칙
컨테이너 div 태그 · class="dynamic-content" · 내용은 비운다 — 다른 태그로는 전개되지 않는다
경로 data-source 는 언제나 「페이지」 기준(./include/…). 파셜 안에서도 같다
값 data-page-title="…" → 파셜 안 {{pageTitle}} · 기본값은 {{pageTitle|페이지 제목}} — React 의 props 자리
마크업 덩어리 data-slot-body="#tpl_id" → 파셜 안 {{{body}}} — React 의 children 자리(같은 파일의 template 요소를 가리킨다)
결과 include 한 div 는 사라지고(replaceWith) 파셜 내용이 그 자리에 들어간다 — React 의 Fragment 처럼 래퍼가 남지 않는다
마무리 고쳤으면 npm run prerender → public/index.html 작업일자 → docs/WORKLOG.md

2. 어떻게 도는가 — 같은 규칙, 두 벌의 구현

브라우저는 실시간으로 끼우고(마운트 뒤), 프리렌더는 같은 결과를 파일로 만든다(SSG 빌드)

런타임과 프리렌더 대응
기능 브라우저 (실시간) 산출물 (개발 인계)
구현 파일 public/js/dynamicImport.js scripts/prerender.js
방식 fetch 로 가져와 치환 후 replaceWith (중첩은 재귀) 같은 규칙으로 문자열 전개 → public/prerender/*.html
변수 RAW_RE / ESC_RE 블록 partialVars() / fillVars()
슬롯 data-slot-* 처리 블록 resolveSlots() / fillSlots() 
DOMContentLoaded
  → 파셜 주입 (재귀)                 dynamicImport.js
  → 'dynamic-content-loaded' 발생
  → JSON 목록 렌더                   listRender.js  (파셜이 있으면 이 이벤트를 기다린다)
  → 'dynamic-list-loaded' 발생
  • 파셜이 먼저, 목록이 나중이다. 그래서 파셜 안에 목록 컨테이너를 넣어도 된다.
  • 파셜이 들어온 뒤에 잡아야 하는 스크립트는 dynamic-content-loaded 에 건다. 공통 UI(common.js)는 문서 위임이라 나중에 주입된 파셜에서도 그냥 동작한다 — 페이지에 전용 스크립트를 두지 않는다.

두 구현 중 한쪽만 고치지 않는다. 규칙이 갈리면 「화면은 되는데 산출물이 다르다」가 된다.

3. 부르는 쪽 규칙

이 여섯 가지를 지키면 브라우저와 산출물이 같아진다

부르는 쪽 규칙
규칙 이유 · 어기면
태그는 div 프리렌더가 div 만 잡는다(PARTIAL_RE). span·li·td 자리에는 파셜을 못 넣는다 — 문장 한가운데 툴팁을 넣지 못하는 이유다(.ui-label 을 flex 로 두고 옆에 둔다)
컨테이너는 비운다 <div …></div>. 안에 내용을 적으면 전개 대상이 아니다. 슬롯도 내용을 넣지 않고 template 요소를 가리킨다
경로는 페이지 기준 fetch 가 문서 기준이라 파셜 안에서도 ./include/… 로 적는다. 파셜 위치 기준(./_x.html)으로 적으면 404
class 를 더 줘도 사라진다 replaceWith 라 래퍼가 남지 않는다. 위치 보정은 형제 셀렉터나 파셜이 받는 data-modifier 로 한다
주석 처리하면 전개되지 않는다 런타임·프리렌더 모두 주석 안은 건너뛴다. 잠깐 끄고 싶을 때 안전하게 쓸 수 있다
순환 include 를 만들지 않는다 프리렌더는 경고하고 건너뛰지만 브라우저에는 방어가 없다 — 요청이 멈추지 않는다

4. 값 넘기기 — data-* 를 {{key}} 로 받는다

React 의 props 와 같은 자리다 — 문구 한 줄이 다르다고 파셜을 두 벌 만들지 않는다

4-1. 문법

변수 문법
문법 뜻
키 이름 data-page-title → {{pageTitle}} (케밥 → 카멜)
{{key}} HTML 이스케이프해서 넣는다
{{{key}}} 원문 그대로 넣는다 — 태그 · 속성 묶음을 넘길 때
{{key|기본값}} 넘기지 않으면 기본값. 빈 기본값은 {{name|}}

기본값이 없는 키를 넘기지 않으면 {{key}} 가 화면에 글자로 남는다. 여러 화면이 쓰는 파셜은 필수 값 외에는 전부 기본값을 준다.

data-* 키에 대문자를 쓰지 않는다. data-makeNew 는 브라우저에서 dataset.makenew 가 돼 브라우저만 치환에 실패한다(프리렌더는 성공). 속성은 큰따옴표로 적는다 — 작은따옴표는 그 반대로 프리렌더만 실패한다.

동작 — 같은 파셜에 값만 바꿔 넣는다

<div class="dynamic-content" data-source="./include/guide/_guide_var.html"
	data-title="값을 넘긴 화면"
	data-msg="따옴표 &quot;큰따옴표&quot; · 꺾쇠 &lt;b&gt; · 앰퍼샌드 &amp;"
	data-msg-raw="원문이라 <b>태그가 살아난다</b>"
	data-modal-id="modal_invite" data-max-size="10MB"
	data-with-default="넘긴 값이 기본값을 이긴다"></div>

값을 넘긴 화면

치환 결과
파셜에 적은 것 화면에 나온 것
A · 이스케이프 {{msg}} {{msg}}
B · 원문 {{{msgRaw}}} 원문이라 태그가 살아난다
C · 안 넘긴 키 {{notPassed}} (기본값 없음) {{notPassed}}
D · 속성값 자리 data-id="{{modalId}}"
E · 케밥 → 카멜 data-max-size → {{maxSize}} 10MB
F · 기본값 {{withDefault|…}} 넘긴 값이 기본값을 이긴다

아무것도 안 넘긴 화면

치환 결과
파셜에 적은 것 화면에 나온 것
A · 이스케이프 {{msg}} {{msg}}
B · 원문 {{{msgRaw}}} {{{msgRaw}}}
C · 안 넘긴 키 {{notPassed}} (기본값 없음) {{notPassed}}
D · 속성값 자리 data-id="{{modalId}}"
E · 케밥 → 카멜 data-max-size → {{maxSize}} {{maxSize}}
F · 기본값 {{withDefault|…}} 넘기지 않으면 이 문구가 들어온다

두 카드를 나란히 본다. 같은 파셜이고 다른 것은 data-* 뿐이다 — C 행은 두 화면 모두 {{notPassed}} 가 글자로 남고, F 행만 기본값으로 채워진다.

4-2. 문구가 아닌 자리 — class · 속성 · style

치환은 글자 바꿔치기라 넣는 자리를 가리지 않는다. 속성값이면 어디든 들어간다 — class 이름 · 속성 · style · href 안까지. 

<!-- 모양만 다르다 : class 이름을 값으로 받는다 -->
<button class="ui-btn {{variant|ui-btn--outlined}}">

<!-- 있다 / 없다 : 속성 묶음을 통째로 받는다(공통 체크박스가 실제로 이 모양이다) -->
<input type="checkbox" {{{attrs|}}} />      <!-- data-attrs="checked disabled" -->

<!-- 길이 · 색 : style 안도 그냥 글자다 -->
<i style="width: {{width|10}}%"></i>

참 · 거짓을 문자열로 넘기지 않는다. data-attrs="false" 는 <input false> 가 되고 class 자리면 class="ui-btn false" 가 된다 — 끄는 방법은 「안 넘기는 것」 하나뿐이다.

빈 값을 넘기는 것과 안 넘기는 것은 다르다. data-variant="" 는 「넘긴 것」이라 기본값을 이긴다. 기본값을 쓰려면 속성을 아예 적지 않는다.

속성 자리에 원문 치환을 쓸 때는 값에 " 가 없어야 한다. 하나라도 있으면 속성이 거기서 끊긴다 — 아래 4-3 의 href 행과 같은 이유다.

값을 넘긴 화면

style="width: {{width|10}}%"

4-3. 이스케이프와 원문 — 어느 쪽을 쓰나

이스케이프와 원문 대조
무엇이 {{key}} — 이스케이프 {{{key}}} — 원문
값에 태그가 들어 있으면 & < > " ' 가 엔티티로 바뀌어 글자로 보인다 마크업으로 살아난다
속성값 자리
href="…" · style="…"		 안전하다 — " 가 &quot; 로 나가고 브라우저가 되돌려 읽는다 따옴표가 깨진다. 값에 " 가 하나라도 있으면 속성이 거기서 끊긴다 — 대신 속성 묶음 전체를 받는다
언제 쓰나 기본. 개발단에서 사용자 입력이 들어올 자리는 반드시 이쪽 신뢰할 수 있는 값 · 개수가 변하는 조각 · 속성 묶음({{{attrs|}}})
두 패스의 순서 두 번째로 돈다 먼저 돈다 — 그래서 원문으로 꽂은 값 안에 중괄호가 있으면 두 번째 패스가 그것을 다시 훑는다

4-4. 같은 괄호, 다른 규칙 — 파셜 변수와 목록 템플릿

파셜 변수와 목록 템플릿 대조
무엇이 파셜 변수 — data-* 목록 템플릿 — JSON
값은 어디서 오나 부르는 쪽의 data-* 속성 JSON 배열의 항목 하나
안 넘긴 키 중괄호가 그대로 남는다 — 화면에 {{explain}} 이 찍힌다 빈 문자열로 사라진다 — 경고가 없다
왜 다른가 파셜 안에 목록 template 이 들어 있을 때 그쪽 키를 먼저 먹지 않으려고 값이 없는 칸은 비우는 것이 맞아서 → JSON 이 모든 필드를 갖는다
기본값 {{key|기본}} 된다. 기본값은 이스케이프하지 않는다(파셜에 직접 쓴 HTML 이라) 안 된다. 정규식이 | 를 몰라 매치 자체가 안 돼 중괄호가 글자로 남는다
순번 없다 {{@index}} 0부터 · {{@number}} 1부터
마크업 덩어리 data-slot-* → {{{이름}}} 로 받는다 없다 — 행 구조가 다르면 항목의 _tpl 로 템플릿째 바꾼다
구현 prerender.js 의 fillVars() · dynamicImport.js 의 같은 블록 listRender.js 의 fillTemplate() · prerender.js 의 같은 함수

파셜 안 목록 템플릿에는 | 를 쓰지 않는다. 「안 넘긴 키를 그대로 둔다」는 보호는 기본값이 없을 때만 든다 — {{name|이름없음}} 은 파셜 변수 패스가 먼저 채워버려 listRender 가 볼 것이 남지 않는다.

개발단에 넘기는 표시 마커는 영문 한 단어만 쓰지 않는다. 키 형식이 [\w@.-]+ 라 {{Pro}} 는 키로 잡혀 지워지거나 치환된다 — 한글 · 공백 · 태그를 섞는다({{플랜 구독하기}}).

4-5. 조건문이 없다 — 기본값이 곧 else 가지다

{{a ? b : c}} 같은 문법은 없고, 앞으로도 두지 않는다. 파셜은 판단하지 않는다 — 어느 쪽인지는 부르는 화면이 이미 알고 있다. 그래서 조건이 아니라 결과를 넘긴다.

  • 두 갈래 — 기본값 쪽이 else 다.
  • 세 갈래 이상인데 모양만 다르다 — class 로 받는다(4-2).
  • 마크업째 있다 / 없다 — 경로 변수(5).
  • 본문이 다르다 — 슬롯(6). 구조가 다르다 — 항목의 _tpl(7).
  • 런타임에 갈린다 — 퍼블이 정할 일이 아니다. 마크업에 두고 개발단에 주석으로 넘긴다.

전체 갈래는 8. 어느 것을 고를까 한 장에 모아 두었다.

React 라면

파셜은 data-page-title="회원 관리" 로 넘기고 {{pageTitle|페이지 제목}} 로 받는다. 같은 일을 React 는 이렇게 한다. 

// props 로 넘기고, 기본값은 매개변수 기본값으로 둔다
function Header({ pageTitle = '페이지 제목' }) {
	return <h1 className="app-header__title">{pageTitle}</h1>;
}

<Header pageTitle="회원 관리" />

5. 덩어리를 통째로 넣고 뺀다 — data-source 를 변수로 연다

파셜 하나를 여러 화면이 쓰는데 한 덩어리만 어떤 화면엔 없어야 할 때. 문구가 아니라 마크업이 통째로 빠지므로 4 의 값 치환으로는 안 된다 

<!-- 공통 파셜 : 갈아끼울 자리를 「경로 변수」로 비워 둔다 -->
<div class="dynamic-content" data-source="{{extra|./include/common/_none.html}}"></div>

<!-- ① 덩어리가 필요한 화면 : 조각의 경로를 넘긴다 -->
<div class="dynamic-content" data-source="./include/guide/_guide_optional_host.html"
	data-extra="./include/guide/_guide_optional.html"></div>

<!-- ② 필요 없는 화면 : 아무것도 넘기지 않는다 → 기본값인 빈 파셜이 들어온다 -->
<div class="dynamic-content" data-source="./include/guide/_guide_optional_host.html"></div>

① 경로를 넘긴 화면

틀 — 어느 화면에서나 나온다

이 문단은 틀에 있으므로 두 경우 모두 나온다.

이 덩어리는 경로를 넘긴 화면에만 나온다. 안 넘긴 화면의 산출물에는 한 줄도 나가지 않는다 — CSS 로 감춘 것이 아니라 애초에 그려지지 않는다.

② 넘기지 않은 화면

틀 — 어느 화면에서나 나온다

이 문단은 틀에 있으므로 두 경우 모두 나온다.

경로 변수 규칙
항목 규칙
빈 파셜 include/common/_none.html 은 0바이트 빈 파일이다. 주석 한 줄도 넣지 않는다 — 짧은 주석은 「구역 표시」로 판정돼 산출물에 그대로 남는다
기본값은 필수 기본값 없이 {{extra}} 로 두면 안 넘긴 화면에서 토큰째 fetch 한다 → 브라우저는 404, 프리렌더는 ! 파셜 없음
산출물에 뭐가 남나 replaceWith 라 컨테이너까지 사라진다 — 끈 화면의 산출물에는 죽은 마크업이 한 줄도 안 나간다
중첩도 그대로 치환이 끝난 뒤 다시 전개하므로(fillVars → expandPartials) 넣은 조각 안에 또 include 가 있어도 풀린다. 브라우저도 같은 순서다
실물 모달 프레임이 버튼 영역을 갈아 끼우는 data-footer 가 같은 모양이다 — 비우는 쪽이 아니라 바꾸는 쪽으로 쓴 예

CSS 로 감추지 않는다. display: none 으로 끄면 산출물에 죽은 마크업이 그대로 남아 개발자가 그것을 옮겨 쓴다. 「이 화면에는 없다」는 없애는 것이지 감추는 게 아니다.

조각이 두세 벌로 늘어나면 변수 대신 파셜을 나눈다. 이 방식은 있다 / 없다 한 가지일 때가 제일 깔끔하다 — 버튼이 없는 모달을 _ui_modal_alert.html 로 따로 둔 것이 그 판단이다.

React 라면

파셜은 경로를 넘기거나 넘기지 않는 것으로 가른다. 같은 일을 React 는 이렇게 한다. 

// 넘기면 그리고, 안 넘기면 아무것도 그리지 않는다
function Host({ extra = null }) {
	return <div className="ui-card__body"><p>…</p>{extra}</div>;
}

6. 슬롯 — 마크업 덩어리를 넘긴다

React 의 children 자리 — 값이 문구가 아니라 여러 줄 마크업이면 data-slot-* 로 넘긴다 

<!-- 부르는 쪽 : 컨테이너는 비우고, 내용은 같은 파일의 template 에 적는다 -->
<div
	class="dynamic-content"
	data-source="./include/ui/_ui_modal.html"
	data-id="modal_invite"
	data-title="멤버 초대"
	data-slot-body="#modal_invite_body"
></div>

<template id="modal_invite_body">
	<div class="grid">…</div>
</template>

<!-- 받는 쪽(_ui_modal.html) -->
<div class="ui-modal__body">{{{body}}}</div>
슬롯 문법
항목 규칙
키 이름 data-slot-body → 파셜 안 {{{body}}}
값 template 요소의 아이디 선택자(#아이디) — 마크업을 속성에 직접 적지 않는다
template 위치 include 를 적은 같은 파일(페이지든 파셜이든). 산출물에서는 정의가 걷힌다
없어도 되는 슬롯 파셜에 {{{body|}}} — 넘기지 않으면 프리렌더가 그 줄을 지운다
  • 슬롯 안에서 파셜을 include 할 수 있다. 여러 화면이 함께 쓰는 본문은 template 안에서 그 파셜을 부른다.
  • 슬롯은 항상 세 겹이다. 두 겹으로 적으면 태그가 글자로 보인다.

슬롯 이름을 파셜 안 목록 템플릿의 필드명과 겹치지 않게 짓는다. 겹치면 목록 필드 자리까지 슬롯 내용으로 덮인다(아코디언은 항목 필드로 {{{body}}} 를 쓴다).

본문을 어디에 두나

본문은 template 안에 직접 적어도 되고, 파셜로 빼고 template 이 그 파셜만 부르게 해도 된다. 기준은 길이와 재사용이다 — 처음부터 다 파일로 만들면 파일만 늘어난다.

본문을 어디에 두나
본문이 이렇다면 이렇게
10줄 안팎 · 그 화면 전용 부르는 파일의 template 안에 직접 적는다 — 파일을 따로 만들 이유가 없다
입력 · 표가 들어가 30줄을 넘는다 <슬라이스>/body/ 파셜로 빼고 template 은 그 파셜만 부른다
두 화면 이상이 같은 본문을 쓴다 <슬라이스>/body/ 파셜 — 두 곳이 되는 순간 옮긴다. 다만 id 를 고정으로 가진 본문은 한 페이지에 두 번 넣지 않는다(id 가 겹친다)
개발 인계에서 따로 떼어 봐야 한다 <슬라이스>/body/ 파셜 — 파일 하나가 화면 하나의 본문이 된다

파셜로 뺄 때는 슬라이스 폴더 아래 body/ 세그먼트에 모은다. data/<슬라이스> 와 이름을 맞추면 데이터와 마크업이 대칭이 된다. 폴더 규칙 전체는 폴더 구조 — 어느 폴더에 두나. 

public/html/include/
├─ ui/         _ui_modal.html …            ← 프레임 (본문을 직접 부르지 않고 슬롯으로 받는다)
└─ sample/                                 ← 슬라이스 (data/sample 과 같은 이름)
   ├─ section/ _sample_overlay.html …      ← 화면을 이루는 덩어리
   └─ body/    _sample_invite_body.html    ← 슬롯 본문

파일       include/sample/body/_sample_invite_body.html
template   id="sample_invite_body"
모달       data-id="sample_invite"

파일 이름 · template 아이디 · 모달 data-id 를 한 규칙으로 묶으면 grep 한 번에 다 잡힌다.

template 째 파셜로 빼면 — 순서에 묶인다

위는 본문 마크업만 파셜로 뺀 형태다. template 요소째 파셜로 빼는 것도 되지만, 파셜은 적힌 순서대로 전개되므로 뒤에 둔 파셜의 template 은 슬롯을 채울 때 아직 없다.

template 배치별 동작
배치 브라우저 프리렌더
template 이 include 보다 뒤 (같은 파일) ✅ ✅
template 이 include 보다 앞 (같은 파일) ✅ ✅
template 째 파셜로 빼고 사용처보다 앞에서 include ✅ ✅
template 째 파셜로 빼고 사용처보다 뒤에서 include ❌ 본문이 빈 채로 렌더 (콘솔 경고만) ❌ ! 슬롯 template 없음 경고

못 찾으면 조용히 빈 본문으로 나간다. 그래서 template 은 include 를 적은 파일에 둔다. 굳이 한곳에 모아 두려면 모든 사용처보다 앞에서 include 한다.

React 라면

파셜은 data-slot-body="#modal_invite_body" 로 넘기고 {{{body}}} 자리에 꽂는다. React 의 children 과 같다. 

// 여러 줄 마크업은 children 으로 넘긴다
function Modal({ title, children }) {

7. 파셜과 목록(JSON)

React 의 map 자리 — 파셜이 먼저 주입되므로 파셜 안에 목록 컨테이너와 템플릿을 함께 둘 수 있다 

<!-- 부르는 쪽 -->
<div
	class="dynamic-content"
	data-source="./include/ui/_ui_dropdown.html"
	data-items="../data/ui/sample_options.json"
></div>

<!-- 받는 쪽(_ui_dropdown.html) -->
<ul
	class="dynamic-list"
	data-source="{{items}}"
	data-template="#tpl_ui_dropdown_item"
	data-empty="#tpl_ui_dropdown_empty"
></ul>
<div class="dynamic-content" data-source="./include/ui/_ui_dropdown_tpl.html"></div>
  • 목록 경로(data-items)는 ../data/… — 목록도 페이지 기준이다.
  • 템플릿만 담은 파셜(_ui_dropdown_tpl.html)을 따로 두면 여러 파셜이 템플릿을 함께 쓴다(드롭다운 · 검색 드롭다운).

파셜 안 목록 템플릿의 {{name}} 은 파셜 변수와 같은 괄호다. 파셜에 같은 이름을 넘기면 파셜 변수가 먼저 먹는다 — 이름을 갈라 쓴다.

React 라면

파셜은 속성 네 개가 이 일을 한다 — data-source(데이터) · data-template(행 모양) · data-filter(거르기) · data-empty(0건). 

// 거르고 · 돌리고 · 0건이면 다른 것을 그린다
{items.length === 0 ? (
	<Empty />
) : (
	items.filter((it) => it.group === 'input').map((it) => <Row key={it.name} {...it} />)
)}

템플릿만 담은 파셜 — 여러 파셜이 행 모양을 함께 쓴다

행 마크업을 두 곳 이상이 쓰면 template 요소만 담은 파셜을 따로 둔다 — 드롭다운과 검색 드롭다운이 _ui_dropdown_tpl.html 하나를 함께 쓰는 것이 그 모양이다. 

<!-- 페이지 맨 아래에서 include 한다 -->
<div class="dynamic-content" data-source="./include/ui/_ui_dropdown_tpl.html"></div>

목록 template 은 파셜로 빼도 되지만 슬롯 template 은 안 된다. 목록은 파셜 주입이 다 끝난 뒤 쓰이고, 슬롯은 전개 도중 쓰인다 — 사용처보다 뒤에서 include 한 슬롯 template 은 그때 아직 없다(6 참고).

산출물에서는 template 정의가 지워진다(이미 전개했으므로). 남기려면 npm run prerender -- --keep-templates.

운영하며 갈아 끼울 것 — 틀은 파셜, 내용은 JSON

배너 · 팝업 · 공지처럼 앞으로도 계속 갈릴 것은 파셜로 빼는 데서 멈추지 않는다. 틀만 파셜에 두고 내용은 JSON 이 갖는다 — 그러면 다음 것은 데이터 한 줄이다. 

<!-- 틀 : 컨테이너와 template 을 파셜 하나에 둔다 -->
<div class="dynamic-list" data-source="../data/guide/demo_opcomp.json"
	data-template="#tpl_guide_op" data-filter="{{show|use}}"></div>

<template id="tpl_guide_op">
	<div class="guide__op guide__op--{{type}}">   <!-- type 이 그대로 class -->
		<span class="guide__op-txt">{{{txt}}}</span>
	</div>
</template>
  • 컨테이너와 template 을 한 파일에 둔다 — 파셜이 목록보다 먼저 주입되므로 두 경로가 같은 순서로 돈다.
  • type 을 그대로 class 로 쓴다. 변종이 늘어도 템플릿은 하나다 — 스타일 블록만 하나 더한다.
  • 노출은 use 가 정한다. 내린 것은 지우지 않고 거짓으로 둔다 — 다시 올릴 때 한 글자다.
  • 그 줄만 구조가 다르면 항목에 "_tpl" 을 적어 템플릿째 바꾼다.
공지 이 줄은 JSON 한 줄이다. 다음 것을 올릴 때 마크업을 고치지 않는다. 자세히
신규 type 이 그대로 class 가 된다 — 변종이 늘어도 템플릿은 하나다. 사다리 보기
안내 이 줄만 _tpl 로 다른 틀을 골랐다 — 버튼이 없다.

위 네 줄 중 세 줄만 나온다 — 나머지 한 줄은 "use": false 로 내려둔 것이고, 마지막 줄은 _tpl 로 버튼 없는 틀을 골랐다.

같은 JSON 을 좁혀서 — data-filter="type=plus"

위 파셜이 정의해 둔 template 을 페이지의 다른 컨테이너가 그대로 쓴다. 화면마다 다른 것을 띄울 때 data-show 로 넘기는 것이 이것이다.

컴포넌트가 아니라 문자열 치환이다. 상태(useState)도 생명주기도 없고, props 로는 문자열만 넘어간다 — 객체·함수·JSX 는 못 넘긴다. 목록은 JSON 경로로, 마크업 덩어리는 슬롯으로 넘긴다.

값을 안 넘기면 빈칸이 되는 것이 아니라 {{key}} 가 화면에 그대로 남는다. 파셜에 기본값({{key|기본값}})을 적어 둔다.

key 가 없다. 대신 같은 파셜을 한 화면에 두 번 넣을 때는 id 가 겹치지 않도록 파셜이 data-id 를 받는다.

10. 파셜을 새로 만들 때

같은 마크업이 두 곳 이상에 생기면 그 자리에서 파셜로 뺀다

  1. 폴더 — 한 기능만 쓰면 include/<기능>/, 두 곳 이상이 쓰게 되면 common/ 으로 옮긴다(옮길 때 data-source 를 전부 고친다). 공통 UI 는 include/ui/_ui_*.html.
  2. 파일명은 저장소 안에서 고유하게. _ 로 시작한다(프리렌더가 페이지로 오인하지 않는다).
  3. 머리 주석에 「받는 값」을 적는다. 이 저장소의 모든 파셜이 같은 형식이다 — <!-- 공통 입력 — 받는 값 : data-id(필수) · data-placeholder -->
  4. 재사용할 파셜은 id 를 data-* 로 받는다 — id="{{id}}" · id="{{id}}_title". 고정 id 를 박으면 한 페이지에 두 번 못 넣는다.
  5. 활성 상태를 파셜에 박지 않는다. 현재 메뉴·현재 탭은 common.js 가 붙인다.
  6. 새 이름은 grep 으로 충돌 검사하고, 만들었으면 docs/WORKLOG.md 에 한 줄.
  7. npm run prerender 로 파셜 개수가 늘었는지 확인한다 — 페이지마다 ✓ 파일명 (파셜 n / 목록 n · n행) 이 찍힌다.

11. 함정 — 여기서 실수한다

겪은 것만 모았다. 증상이 조용해서 늦게 발견되는 순서로

파셜 함정
함정 무슨 일이 나나 어떻게
div 가 아닌 태그로 include 프리렌더가 전개하지 않아 산출물에만 빈 자리가 생긴다 div 로 두고 레이아웃으로 위치를 맞춘다
컨테이너에 내용을 적음 전개되지 않는다 비운다. 마크업은 슬롯으로 넘긴다
래퍼 클래스가 사라진다 include 한 div 에 준 class 가 없다 형제 셀렉터 · data-modifier
넘기지 않은 키 {{key}} 가 글자로 보인다 — React 처럼 값이 없다고 빈칸이 되지 않는다 파셜에 기본값을 준다(React 의 기본 props 와 같은 자리)
data-* 에 대문자 브라우저만 치환 실패 → 화면과 산출물이 다르다 케밥으로 적는다 (data-make-new)
고정 id 파셜을 두 번 include id 중복 → 라벨·getElementById 가 먼저 것만 가리킨다 id 를 data-* 로 받는다. npm run validate 의 no-dup-id 가 막아 준다
같은 본문 파셜을 슬롯 두 곳에 위와 같은 id 중복 본문 파셜도 id 를 받게 하거나 따로 만든다
슬롯 이름 ↔ 목록 필드명 충돌 목록 템플릿 자리가 슬롯 내용으로 덮인다 이름을 갈라 쓴다 (아코디언은 항목 필드로 {{{body}}} 를 쓴다)
data-text 와 data-slot-body 를 함께 본문이 두 벌 나온다 택일한다
목록 템플릿 안의 include 브라우저에서는 전개되지 않고(목록은 파셜 주입이 끝난 뒤 문자열로 찍힌다) 프리렌더는 펴 버려 화면과 산출물이 갈린다 반복 행 안에는 include 를 두지 않는다 — 템플릿 자체를 파셜로 만든다. 슬롯 template 은 다르다 — 실제 마크업이 되므로 동작한다
JSON 값 안의 {{ }} 치환이 두 번 돌아 마커가 지워진다 중괄호를 엔티티(&#123;)로 적는다 — 이 페이지의 표가 그렇게 만들어졌다
파셜 안 경로를 파셜 기준으로 404 — 화면이 비어 있다 페이지 기준 ./include/…
빈 파셜에 짧은 주석 한 줄 「구역 표시」로 판정돼 산출물에 주석만 남는다 넣지 않는다
설명 주석에 태그를 그대로 프리렌더가 실제 태그로 오인한다 「template 요소」처럼 풀어 쓴다
개발단이 봐야 할 주석 산출물에서 걷힌다 <!--@ … --> 로 표시한다
jQuery 가 필요한 파셜 날짜·기간 파셜은 jQuery UI 로 달력을 그린다 그 페이지에 jquery · jquery-ui 를 넣는다
브라우저 캐시 규칙을 고쳤는데 옛 dynamicImport.js 가 돌아 {{{body}}} 가 글자로 보인다 npm run serve(no-store)로 띄우고 강력 새로고침
Live Server 로 열기 파셜 조각에 라이브리로드 스크립트가 주입돼 마크업이 깨진다 npm run serve (http://localhost:3500) (http://localhost:3500)
template 요소째 파셜로 빼서 사용처보다 뒤에서 include 슬롯을 채울 때 template 이 아직 없어 본문이 빈 채로 나간다 — 프리렌더만 경고를 찍는다 template 은 include 를 적은 파일에 두고, 내용만 <슬라이스>/body/ 파셜로 뺀다
data-* 를 작은따옴표로 브라우저는 읽고 프리렌더는 못 읽는다 — partialVars() 의 정규식이 큰따옴표만 본다. 값이 조용히 기본값으로 떨어진다 큰따옴표로 적는다. npx prettier --write 가 자동으로 맞춘다
빈 값을 넘김 — data-tone="" 「넘긴 것」이라 기본값을 이긴다. 안 넘긴 것과 결과가 다르다 기본값을 쓰려면 속성을 아예 적지 않는다
참 · 거짓을 문자열로 — data-checked="false" 치환은 글자 바꿔치기라 참/거짓을 모른다. <input false> 가 되고 class 자리면 class="ui-tag false" 가 된다 끄는 방법은 「안 넘기는 것」 하나뿐이다
기본값 안에 } 정규식이 [^}]*? 라 거기서 끊긴다 — 기본값이 잘린 채 나온다 중괄호가 필요한 값은 기본값에 두지 않고 넘겨서 채운다
파셜을 「상태 예시」인 채로 복사 파셜은 is-active · is-error 같은 상태를 보여주려 만들어 둔 것이 많다 — 복사하면 그 상태가 따라온다 기준 마크업은 실제 화면에서 가져온다

증상과 원인

{{{body}}} 가 글자로 보인다 슬롯을 안 넘겼다 / template 아이디가 다르다 / 옛 dynamicImport.js(강력 새로고침)

화면은 되는데 산출물만 다르다 include 태그가 div 가 아니다 / 컨테이너에 내용을 적었다 / 두 구현 중 한쪽만 고쳤다

마크업이 깨져 보인다 Live Server 로 열었다 → npm run serve (http://localhost:3500)
class 가 하나 모자라거나 false 가 붙어 있다 빈 값을 넘겨 기본값이 밀렸다 / 참·거짓을 문자열로 넘겼다 — 끄려면 안 넘긴다

산출물에서만 값이 기본값이다 data-* 를 작은따옴표로 적었다 / data-* 에 대문자를 썼다(이쪽은 반대로 브라우저만 실패)

14. 파셜을 고친 뒤

이 순서를 지키지 않으면 index 에서 열어본 화면이 옛것이다

  • npm run prerender — 전체를 돌린다(특정 파일만 돌리면 페이지 간 링크가 404).
  • public/index.html — 그 파셜을 include 한 페이지의 수정일 갱신. 화면·동작이 달라진 페이지에만 찍는다.
  • 신규 파셜이면 docs/WORKLOG.md 에 한 줄(날짜 · 항목 · 위치 · 사유 · 작성자).
  • npm run validate 에 error 가 없다 · 고친 파일은 npx prettier --write 로 정렬.
  • 커밋에 원본과 산출물을 함께 넣는다(커밋 직전 검사가 확인한다).
