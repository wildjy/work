파셜(include) 사용법

0. 한눈에 보기

같은 마크업을 페이지마다 복사하지 않고 public/html/include/ 파일 하나로 두는 방법. 할 수 있는 일은 여섯 가지다 — 처음이면 이 표와 아래 「무엇을 쓸까」만 읽고 필요한 절로 넘어간다.

파셜로 할 수 있는 일
도구 이렇게 쓴다 언제 React 에서는
1. 기본형 <div class="dynamic-content" data-source="/html/include/…/_이름.html"></div> 같은 마크업이 두 곳 이상 컴포넌트 <Header />
3. 값 넘기기 부르는 쪽 data-page-title="…" → 파셜 안 {{pageTitle}} 문구 · class · 속성만 다르다 props
4. 넣고 빼기 파셜 안 data-source="{{extra|/html/include/common/_none.html}}" 어떤 화면엔 덩어리째 없어야 한다 조건부 렌더링 {extra && …}
5. 슬롯 data-slot-body="#본문id" → 파셜 안 {{{body}}} 껍데기는 같고 속만 다르다 children
6. 목록 <tbody class="dynamic-list" data-source="….json" data-template="#tpl_…"> 같은 행이 반복된다 rows.map()
7. 운영 컴포넌트 틀은 파셜, 내용은 JSON — use 로 켜고 type 이 class 배너 · 팝업처럼 계속 갈아 끼운다 데이터 배열 + map

더 알아보기 — 왜 페이지 기준인가
  • 브라우저의 fetch 는 상대경로를 지금 열린 문서(페이지) 기준으로 푼다. 파셜 파일은 문서가 아니라 글자 조각일 뿐이다.
  • 프리렌더도 같은 결과가 나오도록 페이지 폴더를 기준으로 푼다.
  • 깊이가 다른 페이지가 같은 파셜을 쓰면 ../ 를 한 값으로 맞출 수 없다 — 그래서 루트 상대로 적는다. 폴더 규칙 전체는 폴더 구조.

3-0. 이름 규칙 — data-make-new 는 파셜에서 {{makeNew}}

넘기는 쪽(HTML 속성)과 받는 쪽(파셜 안)의 이름 모양이 다르다. 같은 값을 가리키는 두 가지 표기일 뿐이다. 앞의 data- 를 떼고, 하이픈을 지우며 바로 뒤 글자를 대문자로 바꾼다.

data-page-title {{pageTitle}} 하이픈을 지우고 t → T

  • data-source 는 변수가 아니다 — 불러올 파셜의 경로라 파셜 안에서 {{source}} 로 받을 수 없다(두 구현 모두 뺀다).
  • data-slot-이름 은 슬롯이다 — slot- 까지 떼고 남은 이름으로 받는다. data-slot-body → {{{body}}}(5).

  • 왜 안 넘긴 키를 지우지 않나 — 파셜 안에 목록 template 이 들어 있으면 그쪽 {{name}} · {{@number}} 를 먼저 지워 버리기 때문이다(8).
  • 기본값은 이스케이프하지 않는다 — 파셜 작성자가 직접 쓴 HTML 이라 &amp; 가 두 번 바뀌면 안 된다.
  • 기본값 안에는 } 를 쓸 수 없다. 중괄호가 필요한 값은 넘겨서 채운다.
  • {{{attrs|}}} 처럼 빈 기본값이 한 줄을 통째로 차지하면, 넘기지 않았을 때 프리렌더가 그 줄을 지운다(빈 줄이 남지 않게). 넘겼으면 남는다 — 26.09.28 전에는 넘겨도 지워 disabled 가 산출물에서만 빠졌다.

  • 0건 모양 data-empty 는 목록을 만드는 커밋에서 함께 만든다 — 미루면 빈 화면이 검수에서 빠진다. 위 셋째 표가 그것이다.
  • 그 줄만 다른 모양은 JSON 항목에 "_tpl": "#tpl_다른것" — 위 첫째 표의 마지막 줄.
  • 컨테이너는 비워 둔다. JSON 은 한 건이어도 배열 [ { … } ] 로 적는다.

골라 그리기 — data-filter

JSON 은 그대로 두고 이 컨테이너에 그릴 항목만 고른다. 하나의 JSON 을 여러 컨테이너가 나눠 쓸 때 쓴다. 적을 수 있는 모양은 세 가지다.

data-filter 문법
적는 법 고르는 항목 위 demo_rows.json(4건)에서
owner owner 가 참인 것 1건 — 김진학
!owner owner 가 거짓인 것(필드가 없는 것 포함) 3건
role=편집자 role 이 편집자와 같은 것 2건 — 이하늘 · 박서준
안 적음 전부 4건

  • 조건은 하나만 적는다. 「이고 · 또는 · 같지 않음」은 없다 — 필요하면 JSON 에 그 뜻의 필드를 하나 두고("main": true) 그 이름으로 고른다.
  • = 가 있으면 늘 「같다」다. !type=plus 는 「plus 가 아님」이 아니라 이름이 !type 인 필드를 찾아 0건이 된다.
  • 값은 글자로 비교한다 — page=1 은 JSON 의 1 과 "1" 을 둘 다 고른다.
  • 거짓으로 치는 것 — 필드 없음 · false · 0 · 빈 글자 · null. 따옴표 친 "false" 는 참이다.

  • 값을 파셜 변수로 열어 두면 화면마다 고를 수 있다 — data-filter="{{show|use}}"(7).

  • 컨테이너의 class 는 치환되지 않는다. 컨테이너에 class="… {{type}}" 로 적으면 괄호가 그대로 남는다 — template 의 맨 바깥 요소를 본체로 삼는다(대신 컨테이너 div 가 한 겹 남는다).

  • 파셜 변수와 JSON 필드 이름을 겹치지 않는다 — 파셜 변수가 먼저 채워 template 의 같은 이름을 먹는다 (data-show ↔ type 처럼 가른다).
  • JSON 값 안의 개발단 표시 {{ }} 는 영문 한 단어면 지워진다 — 한글 · 공백을 섞는다(8).

8. 동작 원리 — 같은 규칙, 두 벌의 구현

규칙이 왜 그런지 궁금할 때 읽는다. 앞 절의 「✗」 대부분이 여기서 나온다 — 브라우저는 실시간으로 끼우고(마운트 뒤), 프리렌더는 같은 결과를 파일로 만든다(SSG 빌드)

런타임과 프리렌더 대응
기능 브라우저 (실시간) 산출물 (개발 인계)
언제 보나 pnpm run serve 로 /html/… 을 연 작업 화면 index 의 링크 · 개발자에게 넘기는 /prerender/…
구현 파일 public/js/dynamicImport.js scripts/prerender.js
방식 fetch 로 가져와 치환 후 replaceWith (중첩은 재귀) 같은 규칙으로 문자열 전개 → public/prerender/*.html
변수 RAW_RE / ESC_RE 블록 partialVars() / fillVars()
슬롯 data-slot-* 처리 블록 resolveSlots() / fillSlots()

두 구현 중 한쪽만 고치지 않는다. 규칙이 갈리면 「화면은 되는데 산출물이 다르다」가 된다 — 대문자 키 · 작은따옴표(3-0)가 실제로 갈렸던 예다. 의심스러우면 이 페이지를 두 곳에서 각각 열어 결과가 같은지 본다.

도는 순서 — 스크립트는 다 그려진 뒤에

DOMContentLoaded
  → 파셜 주입 (재귀)                 dynamicImport.js
  → 'dynamic-content-loaded' 발생
  → JSON 목록 렌더                   listRender.js  (파셜이 있으면 이 이벤트를 기다린다)
  → 'dynamic-list-loaded' 발생
  • 파셜이 먼저, 목록이 나중이다. 그래서 파셜 안에 목록 컨테이너를 넣어도 된다(6).
  • 파셜 · 목록이 들어온 뒤에 잡아야 하는 스크립트는 dynamic-content-loaded · dynamic-list-loaded 에 건다. 공통 UI(common.js)는 문서 위임이라 나중에 주입된 파셜에서도 그냥 동작한다 — 페이지에 전용 스크립트를 두지 않는다.

같은 괄호, 다른 규칙 — 괄호가 쓰이는 세 곳

같은 {{ }} 를 세 군데서 쓴다. 안 채워졌을 때 어떻게 되는지가 다르다 — 파셜 안이면 파셜 변수, 목록 template 안이면 JSON 필드, 그 밖이면 「개발에서 채운다」는 표시일 뿐이다.

파셜 변수와 목록 템플릿 대조
무엇이 파셜 변수 — data-* 목록 템플릿 — JSON
값은 어디서 오나 부르는 쪽의 data-* 속성 JSON 배열의 항목 하나
안 넘긴 키 중괄호가 그대로 남는다 — 화면에 {{explain}} 이 찍힌다 빈 문자열로 사라진다 — 경고가 없다
왜 다른가 파셜 안에 목록 template 이 들어 있을 때 그쪽 키를 먼저 먹지 않으려고 값이 없는 칸은 비우는 것이 맞아서 → JSON 이 모든 필드를 갖는다
기본값 {{key|기본}} 된다. 기본값은 이스케이프하지 않는다(파셜에 직접 쓴 HTML 이라) 안 된다. 정규식이 | 를 몰라 매치 자체가 안 돼 중괄호가 글자로 남는다
순번 없다 {{@index}} 0부터 · {{@number}} 1부터
마크업 덩어리 data-slot-* → {{{이름}}} 로 받는다 없다 — 행 구조가 다르면 항목의 _tpl 로 템플릿째 바꾼다
구현 prerender.js 의 fillVars() · dynamicImport.js 의 같은 블록 listRender.js 의 fillTemplate() · prerender.js 의 같은 함수

파셜 안 목록 템플릿에는 기본값 | 를 쓰지 않는다. 「안 넘긴 키를 그대로 둔다」는 보호는 기본값이 없을 때만 든다 — {{name|이름없음}} 은 파셜 변수 패스가 먼저 채워버려 listRender 가 볼 것이 남지 않는다.

개발단에 넘기는 표시는 영문 한 단어만 쓰지 않는다. 키 형식이 [\w@.-]+ 라 {{Pro}} 는 키로 잡혀 지워지거나 치환된다 — 한글 · 공백 · 태그를 섞는다({{플랜 구독하기}}).

세 겹으로 넣은 값 안의 괄호는 한 번 더 읽힌다 — 세 겹 → 두 겹 순서로 두 번 채우기 때문이다. 위와 같은 이유로 한글 · 공백을 섞으면 안전하다.

컴포넌트가 아니라 문자열 치환이다. 상태(useState)도 생명주기도 없고, props 로는 문자열만 넘어간다 — 객체·함수·JSX 는 못 넘긴다. 목록은 JSON 경로로, 마크업 덩어리는 슬롯으로 넘긴다.

값을 안 넘기면 빈칸이 되는 것이 아니라 {{key}} 가 화면에 그대로 남는다. 파셜에 기본값({{key|기본값}})을 적어 둔다.

key 가 없다. 대신 같은 파셜을 한 화면에 두 번 넣을 때는 id 가 겹치지 않도록 파셜이 data-id 를 받는다.

10. 파셜을 새로 만들 때

같은 마크업이 두 곳 이상에 생기면 그 자리에서 파셜로 뺀다

  1. 폴더 — 한 기능만 쓰면 include/<기능>/, 두 곳 이상이 쓰게 되면 common/ 으로 옮긴다(옮길 때 data-source 를 전부 고친다). 공통 UI 는 include/ui/_ui_*.html.
  2. 파일명은 저장소 안에서 고유하게. _ 로 시작한다(프리렌더가 페이지로 오인하지 않는다).
  3. 머리 주석에 「받는 값」을 적는다. 이 저장소의 모든 파셜이 같은 형식이다 — <!-- 공통 입력 — 받는 값 : data-id(필수) · data-placeholder -->
  4. 재사용할 파셜은 id 를 data-* 로 받는다 — id="{{id}}" · id="{{id}}_title". 고정 id 를 박으면 한 페이지에 두 번 못 넣는다.
  5. 활성 상태를 파셜에 박지 않는다. 현재 메뉴·현재 탭은 common.js 가 붙인다.
  6. 새 이름은 grep 으로 충돌 검사하고, 만들었으면 docs/WORKLOG.md 에 한 줄.
  7. pnpm run prerender 로 파셜 개수가 늘었는지 확인한다 — 페이지마다 ✓ 파일명 (파셜 n / 목록 n · n행) 이 찍힌다.

같은 본문 파셜을 슬롯 두 곳에 위와 같은 id 중복 본문 파셜도 id 를 받게 하거나 따로 만든다

data-text 와 data-slot-body 를 함께 본문이 두 벌 나온다 택일한다
목록 템플릿 안의 include 브라우저에서는 전개되지 않고(목록은 파셜 주입이 끝난 뒤 문자열로 찍힌다) 프리렌더는 펴 버려 화면과 산출물이 갈린다 반복 행 안에는 include 를 두지 않는다 — 템플릿 자체를 파셜로 만든다. 슬롯 template 은 다르다 — 실제 마크업이 되므로 동작한다
JSON 값 안의 {{ }} 치환이 두 번 돌아 마커가 지워진다 중괄호를 엔티티(&#123;)로 적는다 — 이 페이지의 표가 그렇게 만들어졌다
경로를 ./ 로 (파셜·페이지 기준) 404 — 화면이 비어 있다 루트 기준 /html/include/… — 페이지 깊이와 무관해진다
빈 파셜에 짧은 주석 한 줄 「구역 표시」로 판정돼 산출물에 주석만 남는다 넣지 않는다
설명 주석에 태그를 그대로 프리렌더가 실제 태그로 오인한다 「template 요소」처럼 풀어 쓴다
개발단이 봐야 할 주석 산출물에서 걷힌다 <!--@ … --> 로 표시한다
jQuery 가 필요한 파셜 날짜·기간 파셜은 jQuery UI 로 달력을 그린다 그 페이지에 jquery · jquery-ui 를 넣는다
브라우저 캐시 규칙을 고쳤는데 옛 dynamicImport.js 가 돌아 {{{body}}} 가 글자로 보인다 pnpm run serve(no-store)로 띄우고 강력 새로고침
Live Server 로 열기 파셜 조각에 라이브리로드 스크립트가 주입돼 마크업이 깨진다 pnpm run serve (http://localhost:3500) (http://localhost:3500)
template 요소째 파셜로 빼서 사용처보다 뒤에서 include 슬롯을 채울 때 template 이 아직 없어 본문이 빈 채로 나간다 — 프리렌더만 경고를 찍는다 template 은 include 를 적은 파일에 두고, 내용만 <슬라이스>/body/ 파셜로 뺀다
data-* 값 안의 큰따옴표를 바깥 큰따옴표 안에 그대로 속성이 안쪽 큰따옴표에서 끊긴다 — data-attrs="maxlength="40"" 는 값이 maxlength= 로 잘린다 바깥을 작은따옴표로 감싼다 — data-attrs='maxlength="40"'(26.10.06 부터 프리렌더도 작은따옴표 값을 읽는다 · prettier 도 이 모양으로 맞춘다). 두 따옴표가 다 들어가면 바깥은 큰따옴표, 안쪽 큰따옴표만 &quot;
빈 값을 넘김 — data-cls="" 「넘긴 것」이라 기본값을 이긴다 — class 가 통째로 비어 모양이 사라진다. 안 넘긴 것과 결과가 다르다 기본값을 쓰려면 속성을 아예 적지 않는다. 비우는 것이 목적일 때만 빈 값을 넘긴다 — data-clear=""(지우기 버튼 없앰)
참 · 거짓을 문자열로 — data-checked="false" 치환은 글자 바꿔치기라 참/거짓을 모른다. <input false> 가 되고 class 자리면 class="ui-tag false" 가 된다 끄는 방법은 「안 넘기는 것」 하나뿐이다
기본값 안에 } 정규식이 [^}]*? 라 거기서 끊긴다 — 기본값이 잘린 채 나온다 중괄호가 필요한 값은 기본값에 두지 않고 넘겨서 채운다
파셜을 「상태 예시」인 채로 복사 파셜은 is-active · is-error 같은 상태를 보여주려 만들어 둔 것이 많다 — 복사하면 그 상태가 따라온다 기준 마크업은 실제 화면에서 가져온다
빈 기본값 원문 자리({{{attrs|}}})가 한 줄을 통째로 차지 넘기지 않으면 프리렌더가 그 줄을 지운다(빈 줄이 남지 않게). 넘겼으면 남는다 — 슬롯이든 일반 변수든 같다 그대로 두면 된다. ⚠ 26.09.28 전 prerender.js 는 슬롯만 봐서 data-attrs 를 넘겨도 지웠다 — 짝 프로젝트는 pnpm run sync 로 맞춘다
template 요소 안에 include 브라우저도 프리렌더도 펼치지 않는다. 슬롯으로 꺼내 파셜에 꽂힌 뒤에 펼쳐진다 슬롯 template 안의 include 는 정상 패턴이다. 목록 template 안의 include 는 행에 그대로 남으므로 template 자체를 파셜로 뺀다
파셜 안 코드 예시의 {{key|기본값}} 파셜이 되면 브라우저 · 프리렌더 둘 다 기본값을 채운다 — 보여주려던 코드가 바뀐다({{extra|…}} 는 통째로 사라진다) 예시는 <textarea class="guide__src" data-raw> 안에 적은 그대로 적는다 — 두 구현 모두 안쪽을 건너뛴다. 글자로 보일 & 는 &amp; 로
파셜 안 문장의 {{key|기본값}} 문장 속 인라인 코드도 똑같이 채워진다 중괄호를 엔티티(&#123; · &#125;)로 적는다
목록 template 안의 data-raw 프리렌더가 안쪽을 자리표로 바꿔 두어 모든 행이 {{code}} 글자로 나온다 목록 template 의 textarea 에는 data-raw 를 붙이지 않는다 — {{code}} 의 이스케이프를 textarea 가 다시 푼다

14. 파셜을 고친 뒤

이 순서를 지키지 않으면 index 에서 열어본 화면이 옛것이다

  • pnpm run prerender — 전체를 돌린다(특정 파일만 돌리면 페이지 간 링크가 404).
  • public/index.html — 그 파셜을 include 한 페이지의 수정일 갱신. 화면·동작이 달라진 페이지에만 찍는다.
  • 신규 파셜이면 docs/WORKLOG.md 에 한 줄(날짜 · 항목 · 위치 · 사유 · 작성자).
  • pnpm run validate 에 error 가 없다 · 고친 파일은 pnpm exec prettier --write 로 정렬.
  • 커밋에 원본과 산출물을 함께 넣는다(커밋 직전 검사가 확인한다).
