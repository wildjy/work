3-2. 기본값 — 안 넘기면 무엇이 들어오나

{{이름|기본값}} 으로 적으면 값을 넘기지 않은 화면에는 기본값이 들어간다. 대부분의 화면은 기본값, 다른 화면만 값을 넘긴다.

코드

결과 — ① 안 넘김 · ② 둘 다 넘김

  • 기본값이 없는 키를 안 넘기면 {{memo}} 가 화면에 그대로 찍힌다. 위 ① 의 둘째 줄이 그것이다.
  • 그래서 여러 화면이 쓰는 파셜은 필수 값 외에는 전부 기본값을 준다. 새 화면마다 값을 넘겨야 하는 구조는 결국 하나를 빠뜨린다.
  • 빈 값도 「넘긴 것」이다 — data-btn="" 은 기본값을 이기고 빈 칸이 된다. 기본값을 쓰려면 속성을 아예 적지 않는다.
  • 기본값이 곧 else 다. {{a ? b : c}} 같은 조건 문법은 없고 앞으로도 두지 않는다 — 어느 쪽인지는 부르는 화면이 알고 있으니 결과를 넘긴다. 갈래가 더 많으면 무엇을 쓸까.

더 알아보기 — 기본값의 세부 규칙
  • 왜 안 넘긴 키를 지우지 않나 — 파셜 안에 목록 template 이 들어 있으면 그쪽 {{name}} · {{@number}} 를 먼저 지워 버리기 때문이다(8).
  • 기본값은 이스케이프하지 않는다 — 파셜 작성자가 직접 쓴 HTML 이라 &amp; 가 두 번 바뀌면 안 된다.
  • 기본값 안에는 } 를 쓸 수 없다. 중괄호가 필요한 값은 넘겨서 채운다.
  • {{{attrs|}}} 처럼 빈 기본값이 한 줄을 통째로 차지하면, 넘기지 않았을 때 프리렌더가 그 줄을 지운다(빈 줄이 남지 않게). 넘겼으면 남는다 — 26.09.28 전에는 넘겨도 지워 disabled 가 산출물에서만 빠졌다.
