7. 운영 컴포넌트 — 틀은 파셜, 내용은 JSON

언제 — 배너 · 팝업 · 공지처럼 운영하며 계속 갈아 끼울 것. 틀을 파셜로 빼는 데서 멈추지 않고 내용을 JSON 으로 가르면 다음 것은 데이터 한 줄이다

결과

① 그대로 include — use 가 참인 3줄(마지막 줄은 _tpl 로 버튼 없는 틀)

② 같은 파셜에 data-show="type=plus" — plus 1줄

  • 틀은 컨테이너와 template 을 한 파일에 둔다 — 파셜이 목록보다 먼저 주입되므로 두 경로가 같은 순서로 돈다.
  • 올리고 내리기는 use 한 글자 — 내린 것은 지우지 않고 false 로 둔다.
  • type 이 그대로 class 가 된다 — 새 모양은 스타일 블록 하나로 끝나고 템플릿은 그대로다.
  • 생김새가 아주 다르면 template 을 하나 더 두고 그 줄에 "_tpl" 을 적는다.
  • 태그는 template 이 고정하고 값만 JSON 이 갖는다. 마크업째 받는 것은 개수가 변하는 조각뿐이다.

data-filter="{{show|use}}" — 두 번에 나눠 풀린다

① 파셜 변수가 먼저 괄호를 채우고, ② 목록이 그 조건으로 항목을 고른다. show 는 파셜 변수(페이지가 넘기는 값), use · type 은 JSON 필드다 — 이름이 다른 것이 요점이다.

두 단계로 풀리는 필터
페이지의 include ① 파셜 변수가 채운 뒤 ② 목록이 그리는 것
data-show 안 넘김 data-filter="use" — 기본값 use 가 참인 3줄 (위 결과 ①)
data-show="type=plus" data-filter="type=plus" type 이 plus 인 1줄 (위 결과 ②)
data-show="type=coming" data-filter="type=coming" coming 1줄 — ⚠ use 가 거짓인데도 나온다

조건은 하나뿐이라 type=… 으로 좁히면 use 는 보지 않는다. 내려 둔 항목이 그 type 이면 다시 나온다 — 좁힐 때는 JSON 에서 그 type 이 내려 둔 것인지 확인한다. 필터 문법 전체는 6.

더 알아보기 — 걸리는 곳
  • 컨테이너의 class 는 치환되지 않는다. 컨테이너에 class="… {{type}}" 로 적으면 괄호가 그대로 남는다 — template 의 맨 바깥 요소를 본체로 삼는다(대신 컨테이너 div 가 한 겹 남는다).
  • 값이 비면 빈 자리가 남는다 — 빈 뱃지 · 빈 버튼. 스타일에서 :empty 를 숨긴다.
  • 파셜 변수와 JSON 필드 이름을 겹치지 않는다 — 파셜 변수가 먼저 채워 template 의 같은 이름을 먹는다 (data-show ↔ type 처럼 가른다).
  • JSON 값 안의 개발단 표시 {{ }} 는 영문 한 단어면 지워진다 — 한글 · 공백을 섞는다(8).
