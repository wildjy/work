4. 넣고 빼기 — 어떤 화면에만 있는 덩어리

언제 — 파셜 하나를 여러 화면이 쓰는데 한 덩어리만 어떤 화면엔 없어야 할 때. 글자가 아니라 마크업이 통째로 빠지므로 값 넘기기(3)로는 안 된다

끼울 조각 — _guide_optional.html

② 필요 없는 화면 — 아무것도 안 넘긴다

코드

결과 — 틀만 남고 조각은 한 줄도 안 나간다

  • 이름 — 페이지는 data-extra 로 넘기고 파셜은 {{extra}} 로 받는다(3-0).
  • 기본값은 빈 파셜 /html/include/common/_none.html 이다. 0바이트 빈 파일이고 주석 한 줄도 넣지 않는다 — 짧은 주석은 「구역 표시」로 판정돼 산출물에 남는다.
  • 기본값을 꼭 준다. 없으면 안 넘긴 화면이 {{extra}} 라는 경로를 불러 브라우저는 404, 프리렌더는 ! 파셜 없음.
  • 안 넘긴 화면의 산출물에는 빠진 덩어리가 한 줄도 남지 않는다 — include div 까지 사라진다.
  • 조각이 두세 벌로 늘어나면 변수 대신 파셜을 나눈다. 이 방법은 있다 / 없다 한 가지일 때 가장 깔끔하다 — 버튼 없는 모달을 _ui_modal_alert.html 로 따로 둔 것이 그 판단이다.

✗ CSS 로 감췄다 — 산출물에 죽은 마크업이 남아 개발자가 옮겨 쓴다

✓ 필요한 화면만 경로를 넘긴다 — 나머지는 아예 안 나간다

React 라면

파셜은 경로를 넘기거나 넘기지 않는 것으로 가른다. 같은 일을 React 는 이렇게 한다.

더 알아보기 — 실물 · 「~일 때만」과 다른 점
  • 실물 — 모달 프레임이 버튼 영역을 갈아 끼우는 data-footer 가 같은 모양이다. 비우는 쪽이 아니라 바꾸는 쪽으로 쓴 예.
  • 「~일 때만 보인다」와 다르다. 로그인 여부처럼 실행 중에 갈리는 조건은 마크업에 두고 주석으로 넘긴다. 이 절은 화면마다 구성이 다른 것 — 아예 안 내보낸다.
  • 치환이 끝난 뒤 다시 전개하므로(fillVars → expandPartials) 끼운 조각 안에 또 include 가 있어도 풀린다. 브라우저도 같은 순서다.
