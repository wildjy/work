0. 한눈에 보기

같은 마크업을 페이지마다 복사하지 않고 public/html/include/ 파일 하나로 두는 방법. 할 수 있는 일은 여섯 가지다 — 처음이면 이 표와 아래 「무엇을 쓸까」만 읽고 필요한 절로 넘어간다.

파셜로 할 수 있는 일
도구 이렇게 쓴다 언제 React 에서는
1. 기본형 <div class="dynamic-content" data-source="/html/include/…/_이름.html"></div> 같은 마크업이 두 곳 이상 컴포넌트 <Header />
3. 값 넘기기 부르는 쪽 data-page-title="…" → 파셜 안 {{pageTitle}} 문구 · class · 속성만 다르다 props
4. 넣고 빼기 파셜 안 data-source="{{extra|/html/include/common/_none.html}}" 어떤 화면엔 덩어리째 없어야 한다 조건부 렌더링 {extra && …}
5. 슬롯 data-slot-body="#본문id" → 파셜 안 {{{body}}} 껍데기는 같고 속만 다르다 children
6. 목록 <tbody class="dynamic-list" data-source="….json" data-template="#tpl_…"> 같은 행이 반복된다 rows.map()
7. 운영 컴포넌트 틀은 파셜, 내용은 JSON — use 로 켜고 type 이 class 배너 · 팝업처럼 계속 갈아 끼운다 데이터 배열 + map

읽는 법. 각 절은 언제 쓰나 → 코드 | 결과 → 규칙 순서다. ✗ / ✓ 는 실제로 틀렸던 것과 고친 모양이고, 「React 라면」은 개발자가 산출물을 옮길 때의 대응이다. 구현 함수 · 이력은 절 끝 더 알아보기를 펼치면 있다.

이 페이지의 헤더와 왼쪽 메뉴도 파셜이고, 표 · 예시 카드 · 데모는 전부 JSON + 템플릿 + 실제 include 로 그린다 — 규약이 깨지면 이 문서가 먼저 무너진다. 문서 판은 docs/PARTIALS.md(같은 JSON 에서 pnpm run docs 로 찍는다).

세 겹 {{{key}}} 는 마지막 수단이다. 여기까지 내려왔다면 「무엇이 다른가」를 잘못 잡은 것이 아닌지 먼저 본다 — 모양만 다르면 class, 구조가 다르면 템플릿, 있다 / 없다면 경로 변수다.

판단이 안 서면 아래쪽(자유로운 쪽)이 아니라 위쪽을 고른다. 위쪽은 할 수 있는 일이 적은 만큼 틀리게 쓸 방법도 적다.
