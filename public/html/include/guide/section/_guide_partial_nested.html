2. 파셜 안의 파셜 — 경로는 늘 같은 모양으로

언제 — 파셜 안에서 또 다른 파셜을 부를 때. 몇 겹이든 풀린다. 헷갈리는 것은 경로 하나뿐이다

코드

결과

  • 경로는 파셜 파일이 아니라 「페이지」 기준으로 풀린다. 같은 폴더의 파셜을 불러도 ./ 로 적으면 안 된다.
  • 그래서 늘 / 로 시작하는 경로(루트 상대)로 적는다 — 어느 깊이의 페이지가 불러도 같은 파일을 가리킨다.
  • 이미지 · 링크 · JSON 경로도 같다 — /images/… · /html/… · /data/….

✗ 파셜 파일 옆이라고 생각했다 — 404

✓ / 로 시작한다

React 라면

컴포넌트 안에서 다른 컴포넌트를 쓰는 것과 같다. 경로 문제는 퍼블 쪽에만 있다 — React 는 import 경로가 따로 있다.

더 알아보기 — 왜 페이지 기준인가
  • 브라우저의 fetch 는 상대경로를 지금 열린 문서(페이지) 기준으로 푼다. 파셜 파일은 문서가 아니라 글자 조각일 뿐이다.
  • 프리렌더도 같은 결과가 나오도록 페이지 폴더를 기준으로 푼다.
  • 깊이가 다른 페이지가 같은 파셜을 쓰면 ../ 를 한 값으로 맞출 수 없다 — 그래서 루트 상대로 적는다. 폴더 규칙 전체는 폴더 구조.
