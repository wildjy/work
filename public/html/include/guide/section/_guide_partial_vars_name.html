3-0. 이름 규칙 — data-make-new 는 파셜에서 {{makeNew}}

넘기는 쪽(HTML 속성)과 받는 쪽(파셜 안)의 이름 모양이 다르다. 같은 값을 가리키는 두 가지 표기일 뿐이다. 앞의 data- 를 떼고, 하이픈을 지우며 바로 뒤 글자를 대문자로 바꾼다.

속성 이름과 받는 이름
속성 (페이지에 적는 것) 파셜 안에서 받는 이름 어떻게 바뀌었나
data-title {{title}} data- 만 뗀다
data-page-title {{pageTitle}} 하이픈을 지우고 t → T
data-make-new {{makeNew}} 하이픈을 지우고 n → N
data-card-title {{cardTitle}} 하이픈이 몇 개든 같다

결과

✗ 속성에 대문자 — 브라우저가 makenew 로 읽어 못 채운다

✓ 속성은 소문자-하이픈, 대문자는 파셜 안 이름에만

  • 속성은 늘 소문자 · 하이픈, 파셜 안의 이름에만 대문자가 생긴다. 거꾸로 적으면 로컬 서버와 index 화면이 갈린다.
  • data-source 는 변수가 아니다 — 불러올 파셜의 경로라 파셜 안에서 {{source}} 로 받을 수 없다(두 구현 모두 뺀다).
  • data-slot-이름 은 슬롯이다 — slot- 까지 떼고 남은 이름으로 받는다. data-slot-body → {{{body}}}(5).
  • 파셜 머리 주석의 「받는 값」은 속성 이름(data-make-new)으로 적는다 — 부르는 사람이 그대로 복사해 쓴다.

대문자는 왜 갈리나 — 브라우저는 속성 이름을 전부 소문자로 바꿔 읽어 data-makeNew 가 dataset.makenew 가 된다. 프리렌더는 글자를 그대로 읽어 makeNew 로 채운다. 기본값이 있으면 브라우저 쪽도 에러 없이 조용히 기본값으로 나와 더 찾기 어렵다.
