5. 슬롯 — 껍데기는 같고 속만 다를 때

언제 — 모달처럼 테두리 · 제목 · 닫기는 같고 본문만 다른 것. 값이 문구가 아니라 여러 줄 마크업이면 data-slot-* 로 넘긴다(React 의 children)

코드

결과 — 틀 하나에 본문만 갈아 끼웠다

  • 문법 — 부르는 쪽 data-slot-이름="#template_id" → 파셜 안 {{{이름}}}. slot- 까지 떼고 남은 이름으로 받는다(3-0). 이름은 자유라 슬롯을 여러 개 둘 수 있다.
  • include div 는 여전히 비운다. 본문은 div 안이 아니라 template 에 둔다.
  • template 은 include 를 적은 같은 파일에 둔다(페이지든 파셜이든). 산출물에서는 정의가 걷히고 채워진 결과만 남는다.
  • 없어도 되는 슬롯은 파셜에 {{{body|}}} — 넘기지 않으면 프리렌더가 그 줄을 지운다.
  • 슬롯은 항상 세 겹이다. 두 겹으로 적으면 태그가 글자로 보인다.

✗ include div 안에 본문을 넣었다 — include 로 알아보지 못한다

✓ 본문은 template 에, div 는 가리키기만

본문을 어디에 두나

본문은 template 안에 직접 적어도 되고, 파셜로 빼고 template 이 그 파셜만 부르게 해도 된다. 기준은 길이와 재사용이다 — 처음부터 다 파일로 만들면 파일만 늘어난다.

본문을 어디에 두나
본문이 이렇다면 이렇게

파셜로 뺄 때는 슬라이스 폴더 아래 body/ 세그먼트에 모은다. data/<슬라이스> 와 이름을 맞추면 데이터와 마크업이 대칭이 된다. 폴더 규칙 전체는 폴더 구조 — 어느 폴더에 두나.

파일 이름 · template 아이디 · 모달 data-id 를 한 규칙으로 묶으면 grep 한 번에 다 잡힌다.

template 째 파셜로 빼면 — 순서에 묶인다

위는 본문 마크업만 파셜로 뺀 형태다. template 요소째 파셜로 빼는 것도 되지만, 파셜은 적힌 순서대로 전개되므로 뒤에 둔 파셜의 template 은 슬롯을 채울 때 아직 없다.

template 배치별 동작
배치 브라우저 프리렌더

못 찾으면 조용히 빈 본문으로 나간다. 그래서 template 은 include 를 적은 파일에 둔다. 굳이 한곳에 모아 두려면 모든 사용처보다 앞에서 include 한다.

React 라면

파셜은 data-slot-body="#modal_invite_body" 로 넘기고 {{{body}}} 자리에 꽂는다. React 의 children 과 같다.

더 알아보기 — 겹치는 이름 · 안쪽 include · 구현
  • 슬롯 이름을 파셜 안 목록 템플릿의 필드명과 겹치지 않게 짓는다. 겹치면 목록 필드 자리까지 슬롯 내용으로 덮인다(아코디언은 항목 필드로 {{{body}}} 를 쓴다).
  • 슬롯 안에서 파셜을 include 할 수 있다. template 안의 include 는 그 자리에서 펼쳐지지 않고, 슬롯으로 파셜에 꽂힌 뒤에 펼쳐진다 — 본문 template 안에 목록 template 을 가진 파셜을 불러도 겹치지 않는다.
  • 파셜 설명 주석에 슬롯 토큰을 그대로 적지 않는다 — 치환은 주석 안도 가리지 않아 본문이 주석에 박힌다.
  • 구현 : prerender.js 의 resolveSlots() · fillSlots() / dynamicImport.js 의 data-slot-* 블록.
