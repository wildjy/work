# 새 화면 · 새 컴포넌트를 시작할 때

## 1. 기존 작업물을 우선 사용한다 (없을 때만 신규 생성 + 안내)

> **원칙:** 새 클래스·컴포넌트·파셜을 만들기 전에 **기존 것이 있는지 먼저 검색**한다.
> 있으면 그대로 재사용하고, 없을 때만 추가하며 **추가한 항목은 반드시 안내·기록**한다.

### 작업 절차

1. **같은 UI 를 쓰는 화면을 먼저 연다** — 클래스명 검색보다 먼저다. 클래스 이름은 하는 일과 다를 수 있고,
   필요한 컴포넌트가 **다른 스코프에 갇혀 있어 검색에 안 걸리기도** 한다.
2. **검색** — `public/html/`, `public/html/include/`, 스타일 폴더, `docs/WORKLOG.md` 에서 찾는다.
3. **있으면 재사용** — 동일 컴포넌트는 새로 만들지 않는다.
4. **없으면 신규 생성 + 안내** — 어떤 이름을, 어디에, 왜(유사 컴포넌트가 없었던 이유) 추가했는지 작업 보고와 WORKLOG 에 남긴다.

> ⚠⚠ **파셜(`include/_*.html`)은 「상태 예시」인 경우가 많다. 기준 마크업으로 삼지 않는다.**
> 편집 화면용 파셜은 `active`·`disabled`·`error` 처럼 **한 상태를 보여주려고** 클래스가 붙어 있고,
> 같은 컴포넌트를 두세 벌 나열해 두기도 한다. 그대로 복사하면 그 상태가 따라온다. **기준은 실제 화면(페이지)에서 가져온다.**

> ⚠ **클래스 이름을 추측하지 않는다.** 시안에서 「제목 + 본문」처럼 묶여 보인다고 감싸는 컨테이너와
> 자식 클래스(`.tit`/`.txt`)가 있을 것이라 짐작하지 않는다. **같은 성격의 기존 마크업을 열어 그 구조를 따른다.**

> ⚠ **기존 선언을 지우거나 바꿀 때는 「그것이 무엇을 대신하고 있었는지」 먼저 확인한다.**
> 시안 값만 보고 갈아끼우면 그 선언이 떠받치던 다른 것이 무너진다. **같은 역할의 형제 블록과 대조한다** — 비대칭이 있으면 그게 이유다.

## 2. 반복되는 실수 — 새로 만들기 전에 이 표부터 확인한다

> 새 이름을 만들거나 공통 컴포넌트를 가져다 쓸 때, 코드를 쓰기 **전에** 해당 줄을 확인한다.
> 🤖 **작업 중 새로운 반복 실수를 발견하면 이 표에 한 줄 추가한다**(날짜 · 무엇이 어떻게 깨졌나 · 확인 방법).

| # | 실수 | 확인 방법 |
| --- | --- | --- |
| 1 | **이미 있는 클래스명·파셜명을 다시 씀** → 기존 규칙이 함께 걸린다 | 새 이름을 정하면 **`grep` 으로 저장소 전체를 먼저 검색**한다. 흔한 이름(`.filter`·`.list_item`)일수록 위험 |
| 2 | **공통 컴포넌트의 크기를 한 값만 덮음** → 나머지가 그대로 남아 어긋난다 | 공통이 **세트로 주는 값**(`min-height`+`line-height`+`padding`)을 함께 덮는다 |
| 3 | **공통 컴포넌트를 「비슷해 보인다」고 채택** | 쓰기 전에 **그 컴포넌트를 이미 쓰는 화면의 마크업**을 연다 |
| 4 | **없는 클래스·아이콘명을 지어냄** | modifier·아이콘은 스타일 파일에 **실제로 있는지 확인**한다 |
| 5 | **반복 목록을 마크업에 찍음** | 5행 이상이면 JSON + `<template>` (`pub-list-render`) |
| 6 | **같은 마크업을 두 페이지에 복사** | 파셜로 뺀다. 문구 차이는 `data-*` 로 넘긴다 (`pub-markup`) |
| 7 | **설명 주석에 태그를 그대로 씀** → 프리렌더가 실제 태그로 오인한다 | `template 요소`·`script 태그`처럼 **풀어 쓴다**. 주석 안 `<template>` 글자가 제거 정규식에 걸리면 **문서 뒷부분 전체가 주석으로 먹힌다** |
| 8 | **상태마다 위치 값을 달리 줘서 토글 시 흔들림** | `align-items`·`line-height` 처럼 **위치에 영향을 주는 값은 고정**하고, 상태에서는 색·그림자·표시만 바꾼다 |
| 9 | **상태 클래스(`.is_*`)로 감췄는데 안 가려짐** | 그 요소에 **이미 `display` 를 주는 규칙의 특정성**을 센다. 감출 클래스는 **사라져야 하는 요소 자신**에 걸고 같은 깊이 이상으로 적는다 |
| 10 | **카드·패널 폭을 `flex: 1` 균등분할에 맡김** | 시안은 **고정폭**인 경우가 많다. 실측값을 적고 `카드×n + gap×(n−1) + 좌우 패딩 = 부모 폭` 으로 **검산**한다 |
| 11 | **실측에서 「확인 불가」로 나온 값을 대화에만 적고 넘어감** | 특히 **색은 빠져도 깨지지 않아** 그럴듯하게 보인다. ① 렌더로 한 번 더 시도 ② 그래도 못 정하면 **그 자리 마크업에 주석으로 박는다** — `<!--@ 색 미정 : 시안 mixed 텍스트라 판정 불가. 디자이너 확인 후 반영 -->` |
| 12 | **「라벨 + 숫자」를 한 덩어리로 보고 구현** → 숫자 강조가 빠진다 | 문자열에 숫자·단위가 섞여 있으면(`대상 18명`·`4.2GB / 20GB`) **구현 전에 `scan_text_nodes`** 를 돌린다(§4) |
| 13 | **조사 대상을 확정하지 않고 위임** | 「선택 레이어」는 **`get_selection` 을 직접 먼저.** 위임 범위는 노드 하나가 아니라 **부모·형제까지** |
| 14 | **「실측」이라는 말만 보고 에이전트에 위임** | 컴포넌트 하나는 `get_node_info` **1~2회로 끝난다.** 위임은 아트보드 여러 개 · 상태 여러 벌 · 렌더 판정 반복일 때만 |
| 15 | **시안 색 두 개를 비슷하다고 하나로 합침** → 정보 위계가 사라진다 | 토큰으로 치환하되 **단계 수는 시안 그대로** 유지한다. 가장 가까운 토큰을 고르고 근거를 주석에 남긴다 |

## 3. 새 화면을 시작할 때의 순서

1. **시안 전체 아트보드를 먼저 센다** — 화면 하나만 보고 시작하면 나중에 구조가 뒤집힌다
2. 쓸 컴포넌트를 **검색**한다(§1) — **같은 UI 를 쓰는 화면**을 먼저 연다
3. **상태가 몇 개인지** 센다 → 여러 개면 전환 + 상태별 페이지(`pub-markup` §5)
4. **반복 목록**이 있는지 본다 → JSON + 0건 상태(`pub-list-render`)
5. 새 이름은 **충돌 검사**(§2 표 1)
6. 색이 토큰에 없으면 **작업 전에 질문**한다
7. 만들고 나면 **시안과 1:1 대조** — 폰트·간격·색을 각각 확인한다
8. 마무리 : 프리렌더 → index 작업일자 → WORKLOG

## 4. Figma 시안 판독 — MCP 가 안 주는 것

| 안 주는 것 | 탐지·대응 |
| --- | --- |
| **effects(그림자)** | 응답 필드에 없다. `export_node_as_image` 로 내보내 **산출 이미지가 노드 크기보다 크면 그림자가 있다**. 여백으로 blur·offset 을 역산한다(색·투명도는 확인 불가) |
| **`cornerRadius`** | 응답에 없을 수 있다. 카드·버튼은 렌더로 한 번 더 본다 |
| **Boolean 연산 도형의 path** | 자식만 오고 합쳐진 path 가 없다. SVG export 도 렌더 이미지만 온다 → **작업자에게 원본 SVG 를 요청**한다 |
| **노드의 `visible`** | `get_node_info` 는 안 준다(`get_selection` 만). 단 `fills[]`/`strokes[]` 안의 `"visible": false` 는 온다 → **꺼진 테두리를 테두리로 오인하지 않는다** |
| **mixed 텍스트의 뒷 구간 색·굵기** | ⚠ **필수 절차** — 숫자·단위가 섞인 문자열은 무조건 먼저 돌린다. `scan_text_nodes` 로 **`fontFamily`/`fontStyle` 이 빈 문자열("")** 인 노드를 찾는다. 값은 `export_node_as_image` **scale 4 이상**으로 내보내 픽셀로 판정한다(가장자리 안티앨리어싱은 피한다) |
| **「값 + 단위」가 형제 TEXT 여러 개** | `₩ 400,000원 / 년` 이 실제로는 TEXT 노드 여러 개이고 **뒤쪽만 흐린** 경우가 많다. mixed 가 아니라 빈 문자열 검사에 안 걸린다 → **bbox 안 TEXT 개수를 먼저 센다**. bbox 밖에 클리핑된 **원본 컴포넌트 잔재 텍스트**는 옮기지 않는다 |
| **`fills[]` 가 SOLID 가 아닐 때** | `fills[0].color` 만 읽으면 그라데이션이 `undefined` 로 조용히 빠진다. `type` 을 먼저 보고 `gradientStops`·`gradientTransform` 을 읽는다 |
| **`strokeWeight`·`strokeAlign`** | 색만 온다. `bbox − 콘텐츠 인셋` 으로 역산한다(예: `360 − 318 = 42 = (1+20)×2` → 1px INSIDE + padding 20) |
| **auto-layout 의 padding·itemSpacing** | 응답에 없다. **자식 bbox 좌표 차**로 계산하고, **합이 부모 높이와 맞는지 검산**한다 |

- **간격은 계산해서 낸다.** 「라벨 시작 → 입력 시작」은 라벨 폭 + 간격이다 → `입력 x − (라벨 x + 라벨 폭)`.
- **stroke 가 INSIDE 면 노드 bbox = 테두리 바깥**이다.
- **폭이 왜 어긋나는지는 부모까지 본다** — 자식만 봐서는 안 풀린다.
- **커서·포커스 테두리가 함께 그려진 것은 「입력 중 상태」**다. 기본 상태로 읽지 않는다.
- `get_node_info` 응답이 커서 잘리면 **파일로 저장되니** `node -e` 로 파싱한다.
- 원본 SVG 를 받으면 **path 를 건드리지 말고 `viewBox` 의 음수 origin 으로 위치를 맞춘다.**

## 5. 신규 생성 항목은 기록한다

신규 클래스·컴포넌트·파셜·페이지·JS 함수를 추가했으면 **`docs/WORKLOG.md` 맨 아래에 한 줄** 추가한다.

| 날짜 | 항목 | 위치 | 사유 | 작성자 |

사유에는 **재사용한 기존 항목**과 **왜 신규가 필요했는지**를 함께 적는다.
같은 것을 다시 만들려 할 때 `grep -n "이름" docs/WORKLOG.md` 로 과거 판단을 찾을 수 있어야 한다.
