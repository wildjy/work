# 마크업 구조 (파셜 · 동적 표시 · 운영 컴포넌트 · 상태별 페이지)

## 1. 같은 마크업이 **두 곳 이상**이면 파셜로 뺀다

> **원칙:** 레이어(모달)·헤더·탭·필터처럼 **같은 마크업을 두 페이지 이상에서 쓰면**
> `public/html/include/<폴더>/_이름.html` 로 분리하고 include 한다.
> 복사해 두면 **고칠 때마다 전부 찾아 고쳐야 하고, 반드시 하나를 빠뜨린다.**

```html
<div class="dynamic-content" data-source="./include/common/_header.html"></div>
```

### 폴더

- 한 서비스·기능만 쓰면 **그 폴더**(`include/<기능>/`), **두 곳 이상이 쓰게 되면 `common/`** 으로 옮긴다.
  옮길 때는 `data-source` 를 전부 같이 고친다(`grep -rn "_파일명" public/html/`).
- **파셜 파일명은 저장소 안에서 고유하게** 짓는다 — VSCode 의 Alt+D(파일명으로 열기)가 이것에 기대고 있다.
- **접두어는 폴더와 맞춘다.** 다른 서비스가 쓰지 않는데 그 서비스 이름을 달면 혼동을 준다.

### 분리할 때 하는 일

1. **차이를 먼저 통일한다.** id·문구·예시 데이터가 페이지마다 다르면 **하나로 정하거나 §2 의 `data-*` 로 넘긴다.**
2. **여는 버튼 문구도 맞춘다.** 「일괄 선택」/「일괄선택」처럼 갈려 있기 쉽다.
3. 파일 상단에 **사용처·받는 `data-*`·여닫는 방법을 주석으로** 남긴다.
4. include 하는 모든 페이지에 필요한 **JS(`common.js` 등)가 로드**되는지 확인한다.
5. `npm run prerender` 로 산출물을 갱신하고 **파셜 개수가 늘었는지** 확인한다.

### 파셜의 한계 — 이것 때문에 실수한다

| 한계 | 대응 |
| --- | --- |
| **`replaceWith` 라 래퍼 클래스가 남지 않는다** | 위치 보정은 **형제 셀렉터**로 한다. include 하는 div 에 class 를 줘도 사라진다 |
| **활성 상태를 파셜에 넣으면 모든 페이지가 같아진다** | 활성 메뉴·탭은 `common.js` 에서 **현재 파일명과 href 를 대조**하거나 각 페이지의 `dynamic-content-loaded` 에서 토글 |
| **`<template>` 안에서는 include 가 동작하지 않는다** | 템플릿 자체를 파셜로 만든다 |
| **경로는 「페이지」 기준이다** | 파셜 안의 `data-source` 도 페이지 기준으로 쓴다 |
| **빈 파셜에 짧은 주석 한 줄** | 「구역 표시」로 판정돼 산출물에 그대로 남는다 — 넣지 않는다 |

> 🤖 **AI 작업 규칙:** 새 화면을 만들 때 **다른 페이지에 같은 마크업이 있는지 먼저 찾는다.**
> 있으면 복사하지 말고 그 자리에서 파셜로 분리한다. 이미 복사본이 여러 개면 **작업 김에 합친다.**

## 2. 파셜에 **화면별 값을 넘긴다** — `data-*` → `{{key}}`

> **원칙:** 문구 한 줄이 다르다고 파셜을 두 벌 만들지 않는다. **`data-*` 로 넘긴다.**

```html
<!-- 화면(부르는 쪽) -->
<div class="dynamic-content" data-source="./include/common/_header.html" data-page-title="회원 관리"></div>

<!-- 파셜(_header.html) -->
<h1 class="title">{{pageTitle|페이지 제목}}</h1>
```

| | |
| --- | --- |
| 키 이름 | `data-page-title` → `{{pageTitle}}` (dataset 규칙, 케밥 → 카멜) |
| 이스케이프 | `{{key}}` 는 HTML 이스케이프, `{{{key}}}` 는 원문 그대로 |
| 기본값 | `{{key|기본값}}` — 넘기지 않으면 기본값. **기본값은 이스케이프하지 않는다** |
| 구현 | `scripts/prerender.js` 의 `partialVars()`/`fillVars()` · `public/js/dynamicImport.js` 의 같은 블록 |

> ⚠ **넘기지 않은 키(기본값 없음)는 치환되지 않고 `{{key}}` 가 화면에 그대로 남는다.**
> 파셜 안 목록 `template` 의 `{{…}}` 를 보호하려는 설계다. **include 하는 화면이 많으면 반드시 기본값을 준다** —
> 새 화면마다 잊지 않아야 하는 구조는 반드시 하나를 빠뜨린다.
>
> ⚠ **`data-*` 키에 대문자를 쓰지 않는다.** `data-makeNew` 는 브라우저에서 `dataset.makenew` 가 돼
> **브라우저만 치환에 실패한다**(프리렌더는 성공). 기본값이 있으면 조용히 갈려 **index 화면과 serve 화면이 달라진다.** 케밥으로 적는다.
>
> ⚠ **프리렌더와 `dynamicImport.js` 는 같은 규칙을 각각 구현한다 — 한쪽만 고치지 않는다.**
>
> ⚠ 값이 「문구」가 아니라 「데이터 여러 줄」이면 JSON + `template` 으로 간다(`pub-list-render`).

## 3. **개발단이 채울 자리는 `{{ }}` 로 표시한다**

> **원칙:** 정적 화면에서 **예시값일 수밖에 없는 것**은 `{{ }}` 로 감싼다.
> 사용량·금액·개수·날짜, 그리고 조건에 따라 문구가 통째로 바뀌는 자리.

```html
<p class="txt">{{저장 용량이 {{<em>90%</em>}}에 도달했습니다.}}</p>
<a href="#" class="btn">{{플랜 구독하기}}</a>
```

- 검수자가 「하드코딩이 아니라 동적」임을 바로 알고, 개발자는 치환할 자리를 찾는다. 마커는 **화면에 그대로 보인다** — 그게 목적이다.
- **보일지 말지**는 `@` 주석(`<!--@ 인증 전 회원에게만 노출 -->`), **값이 무엇인지**는 `{{ }}`.

### ⚠ 같은 괄호가 세 가지 뜻을 가진다

| 어디에 있나 | 무엇으로 해석되나 | 키를 못 찾으면 |
| --- | --- | --- |
| 파셜 안 (`include/`) | **파셜 변수** (§2) | **토큰이 그대로 남는다** |
| 목록 `template` 안 | **listRender 필드** | **빈 문자열로 지워진다** ⚠ |
| 그 밖의 마크업 | **개발단 표시 마커** | — |

> ⚠ **마커 안에 영문 한 단어만 넣지 않는다.** 키 형식이 `[\w@.-]+` 라 `{{Pro}}`·`{{count}}` 는 **키로 잡힌다.**
> ⚠ **마커 안에 `|` 를 쓰지 않는다** — 기본값 문법으로 오인된다.
> ✅ 한글·공백·태그가 섞이면 안전하다 — `{{플랜 구독하기}}` · `{{<em>90%</em>}}`.

## 4. **운영할 컴포넌트는 틀(파셜)과 내용(JSON)을 가른다**

> **원칙:** 배너·팝업·공지처럼 **앞으로 계속 갈아 끼울 것**은 파셜로 빼는 데서 멈추지 않는다.
> **틀은 파셜, 내용은 JSON** — 다음 것을 올릴 때 **데이터 한 줄만 적으면 된다.**

```
틀   : include/<폴더>/_이름.html   — 컨테이너(.dynamic-list) + <template> 을 한 파일에
내용 : data/<폴더>/이름.json       — use · type · 문구 · 링크
모양 : 스타일 파일의 type 별 블록   — 색 · 배경 · 모션
```

```html
<div class="dynamic-list" data-source="../data/common/banner.json"
     data-template="#tpl_banner" data-filter="use"></div>

<!-- 목록 템플릿 (listRender.js 가 JSON 을 순회해 렌더) -->
<template id="tpl_banner">
	<div class="banner {{type}}">
		<p class="txt">{{{txt}}}</p>
		<a class="btn" {{{link}}}>{{btn}}</a>
	</div>
</template>
<!--// 목록 템플릿 -->
```

1. **파셜 하나에 컨테이너와 템플릿을 같이 둔다.** 파셜이 목록보다 먼저 주입되므로 런타임과 프리렌더가 같은 순서로 돈다.
2. **`type` 을 그대로 class 로 쓴다.** 변종이 늘어도 템플릿은 하나다.
3. **노출은 `data-filter="use"`.** 줄을 지우지 않고 `false` 로 두면 다음에 다시 켤 수 있다.
4. **태그는 템플릿이 고정하고 값만 데이터다.** 예외는 개수가 변하는 조각뿐 — 그것만 `{{{key}}}`.
5. **생김새가 아주 다른 변종은 템플릿을 하나 더 두고 `_tpl` 로 고른다.** 늘리기 전에 「합치면 무엇을 잃는지」를 센다.
6. **화면마다 다른 것을 띄우려면 필터를 파셜 변수로 연다** — `data-filter="{{show|use}}"` + `data-show="type=plus"`.

### ⚠ 함정

| 함정 | 무슨 일이 나나 | 어떻게 |
| --- | --- | --- |
| **컨테이너 class 는 치환되지 않는다** | `<div class="블록 {{type}}" data-template=…>` 는 그대로 남는다 | **템플릿 루트를 본체로** 삼는다 |
| **`{{key\|기본값}}` 이 목록 템플릿에선 안 먹는다** | 파셜 변수 전용이다. 없는 키는 **빈 문자열** | JSON 에 **모든 필드를 채운다** |
| **JSON 이 배열이 아니면 0건** | 객체 하나는 렌더되지 않는다 | `[{ … }]` |
| **빈 값 자리가 남는다** | 값이 없으면 빈 뱃지·빈 버튼이 뜬다 | 스타일에서 `:empty` 를 숨긴다 |
| **파셜 변수와 JSON 필드 이름이 겹치면** | 파셜 변수가 **먼저** 템플릿의 같은 이름을 먹는다 | 키 이름을 갈라 쓴다(`data-show` ↔ `type`) |
| **JSON 값 안의 `{{ }}` 마커가 사라진다** | 치환이 raw → escape **두 번** 돌아 두 번째가 다시 훑는다 | 마커에 한글·공백·태그를 섞는다(§3) |
| **버튼이 화면마다 `href`/`onclick`** | 따로 두면 안 쓰는 쪽이 `href=""` 로 나가 **현재 페이지로 이동** | 속성을 통째로 한 필드에 담아 `{{{link}}}` |
| **설명 주석에 꺾쇠를 쓰면** | 프리렌더가 태그로 오인해 주석이 산출물에 남는다 | 「type 별 블록」처럼 풀어 쓴다 |

> ⚠ **이 파셜을 넣은 화면은 모두 같은 것을 본다**(`use` 는 전역 스위치다).
>
> 🤖 **AI 작업 규칙:** 「앞으로도 바뀔 것」이면 **파셜만 만들고 끝내지 않는다.** 반대로 **한 번 만들고 안 바꿀 것**은 파셜로 충분하다 —
> 기준은 「다음에 또 고칠 것인가」이지 「지금 여러 곳에 쓰는가」가 아니다.

## 5. 상태가 여러 개인 화면은 **전환 페이지 + 상태별 페이지**를 함께 둔다

| | 쓰임 |
| --- | --- |
| **전환 페이지** | 한 화면에서 상태를 바꿔 가며 **동작·전환을 확인**한다. 개발자가 클래스만 토글하면 되는 구조를 보여준다 |
| **상태별 페이지** | `index.html` 에서 **바로 그 상태로 열린다.** 검수·공유·캡처가 쉽다 |

1. **마크업은 파셜 하나**에 모든 상태를 담는다. 상태는 **래퍼의 클래스**로 전환한다.
2. **상태별 페이지**는 파셜을 include 한 뒤 `dynamic-content-loaded` 에서 **상태 클래스를 붙인다**(래퍼에 미리 줄 수 없다 — §1).

```html
<div class="dynamic-content" data-source="./include/member/_member_card.html"></div>
<script>
	document.addEventListener('dynamic-content-loaded', function () {
		var card = document.querySelector('.member_card');
		if (card) card.classList.add('is_closed');
	});
</script>
```

### 이름 규칙 — 기본 화면 이름 뒤에 상태를 붙인다. 「없음/빈 상태」는 `None`.

```
MemberCheckin.html        ← 전환
MemberCheckinDone.html    ← 완료
MemberCheckinNone.html    ← 기간 밖
```

- 상태별 페이지도 **`index.html` 에 등록**한다 — 신규는 두 날짜를 다 채운다.
- 상태가 **레이아웃까지 다르면** 페이지를 나눈다.
- **데이터 유무만 다른 것**(목록 0건)은 `data-empty` 로 처리하고 페이지를 늘리지 않는다.
- **입력 검증 상태**(오류·완료)는 상태 페이지로 만들지 않는다 — 필드별 예시를 한 화면에 담는다.

> 🤖 **AI 작업 규칙:** 상태가 둘 이상인 화면을 만들 때 **전환 페이지 하나로 끝내지 않는다.**
